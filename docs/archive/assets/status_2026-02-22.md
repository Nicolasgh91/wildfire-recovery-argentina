# Estado actual de generación de assets (2026-02-22)

**Documento archivado.** Snapshot de estado; la vista actual está en `docs/STATE.md` y `docs/features/`.

---

## Objetivo

Dejar un corte técnico-operativo sobre:

1. Paso 3 de exploración (HD + PDF),
2. Carrusel/thumbnails de episodios,
3. Brechas reales para release.

## Snapshot ejecutivo

### Operativo hoy

- Flujo de exploración HD asíncrono con job, tracking y assets firmados.
- Generación de PDF integrada como task encadenada al resultado HD listo.
- Carrusel de thumbnails operativo con actualización de metadata por episodio.
- Endpoint de refresh manual de imagery disponible para operación.

### Caveats reales

- El PDF se procesa como task separada dentro del pipeline (no bloquea HD), por eso puede haber casos con HD listo y PDF aún en curso.
- Si `slides_data` no trae URLs válidas, la UI cae en fallback visual.
- Existen rutas legacy/alias que conviven por compatibilidad y pueden confundir lectura documental.

## Estado confirmado backend

### Exploración HD + PDF

- Encolado HD: `POST /api/v1/explorations/{investigation_id}/generate` — `app/api/v1/explorations.py`
- Estado de job HD: `GET /api/v1/explorations/{investigation_id}/generate/{job_id}`
- Assets firmados: `GET /api/v1/explorations/{investigation_id}/assets`
- Task HD: `workers/tasks/exploration_hd_task.py`
- Worker HD: `app/workers/exploration_hd_worker.py`
- Task PDF encadenada: `workers/tasks/pdf_generation_task.py`
- Servicio PDF: `app/services/pdf_generation_service.py`

## Estado confirmado frontend

- Inicio y tracking de generación HD: `frontend/src/pages/Exploration.tsx`
- Polling de estado + carga de assets: `frontend/src/pages/Exploration.tsx`
- Visualización de assets HD y descarga: `frontend/src/pages/Exploration.tsx`
- Sección de PDF disponible en la misma pantalla: `frontend/src/pages/Exploration.tsx`

## Estado de carrusel/thumbnails

- Servicio principal: `app/services/imagery_service.py`
- Task programada: `workers/tasks/carousel_task.py`
- Refresh manual: `app/api/v1/imagery.py`

## Brechas y riesgos vigentes

1. Percepción de "fallo" cuando HD está listo y PDF aún no termina.
2. Tarjetas sin imagen cuando `slides_data` no es utilizable.
3. Coexistencia de rutas/contratos legacy que exige copy claro en docs y UI.

## Próximos pasos recomendados

### Prioridad alta

1. Mejorar mensajes UX de estados HD/PDF para reducir confusión.
2. Endurecer validación de `slides_data` y trazabilidad de causa.
3. Mantener un contrato documental único para rutas canónicas.

### Prioridad media

1. Observabilidad por etapa (latencia HD, latencia PDF, tasa de fallback).
2. Runbook rápido para diagnóstico de assets.
