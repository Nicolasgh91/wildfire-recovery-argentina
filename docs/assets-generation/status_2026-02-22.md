# estado actual de generacion de assets (2026-02-22)

## objetivo

Dejar un corte tecnico-operativo sobre:

1. paso 3 de exploracion (HD + PDF),
2. carrusel/thumbnails de episodios,
3. brechas reales para release.

## snapshot ejecutivo

### operativo hoy

- Flujo de exploracion HD asincrono con job, tracking y assets firmados.
- Generacion de PDF integrada como task encadenada al resultado HD listo.
- Carrusel de thumbnails operativo con actualizacion de metadata por episodio.
- Endpoint de refresh manual de imagery disponible para operacion.

### caveats reales

- El PDF se procesa como task separada dentro del pipeline (no bloquea HD), por eso puede haber casos con HD listo y PDF aun en curso.
- Si `slides_data` no trae URLs validas, la UI cae en fallback visual.
- Existen rutas legacy/alias que conviven por compatibilidad y pueden confundir lectura documental.

## brechas y riesgos vigentes

1. percepción de "fallo" cuando HD esta listo y PDF aun no termina.
2. tarjetas sin imagen cuando `slides_data` no es utilizable.
3. coexistencia de rutas/contratos legacy que exige copy claro en docs y UI.

## proximos pasos recomendados

### prioridad alta

1. mejorar mensajes UX de estados HD/PDF para reducir confusion.
2. endurecer validacion de `slides_data` y trazabilidad de causa.
3. mantener un contrato documental unico para rutas canónicas.

### prioridad media

1. observabilidad por etapa (latencia HD, latencia PDF, tasa de fallback).
2. runbook rapido para diagnostico de assets.

## alcance

- documento tecnico de corte por repositorio local
- no reemplaza validacion E2E en produccion
