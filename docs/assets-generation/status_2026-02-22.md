## Brechas / Gaps Detectados
1. Integración PDF separada del job HD de exploración.
   - Paso 3 hoy combina dos pipelines: HD por `/explorations/.../generate` y PDF por `/reports/judicial`.
2. Posible inconsistencia operativa entre endpoint “home curado” y consumo frontend.
   - Existe `/fire-episodes/active` (`app/api/routes/episodes.py:257`), pero Home consume `/fire-episodes` por `mode`.
3. Thumbnails no visibles cuando `slides_data` está vacío/no utilizable.
   - El frontend cae a fallback visual aunque el flujo técnico de generación exista.
4. Nomenclatura endpoint admin.
   - `refresh/{fire_id}` se procesa como episodio (`refresh_fire -> refresh_episode`), lo que puede inducir ambigüedad semántica.

## Riesgos Inmediatos
- Riesgo funcional: usuarios pueden interpretar que “la generación no funciona” cuando la UI cae al fallback por falta de `slides_data` usable.
- Riesgo de operación: dos flujos separados en paso 3 (HD/PDF) aumentan superficie de fallas parciales y soporte.
- Riesgo de consistencia de producto: diferencias entre endpoint “curado” y consumo real de Home pueden producir resultados no esperados en priorización/visibilidad.
- Riesgo de mantenibilidad: naming ambiguo del endpoint admin puede provocar uso incorrecto o debugging más lento.
